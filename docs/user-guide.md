# Identity Service User Guide

## Purpose

Identity Service is a Java 21 and Spring Boot 4 backend for versioned user
identity management. The API contract is defined first in OpenAPI, while the
application implements generated Spring MVC interfaces and persists users in
PostgreSQL.

## Prerequisites

Install the following tools before running the project:

* Java 21
* Maven 3.9 or the included Maven Wrapper
* Docker Engine or Docker Desktop with Docker Compose

Docker must be running for the integration test suite because Testcontainers
starts a real PostgreSQL container.

## Repository Structure

```text
.github/workflows/ci.yml       Build, Docker validation, and Pages deployment
docs/                          Static dashboard and this user guide
postman/                       Postman collection
src/main/java/                 Application source code
src/main/resources/openapi/    Source OpenAPI contract
src/main/resources/db/         Flyway migrations
src/site/                      Maven site content and navigation
src/test/java/                 Unit, web-layer, and integration tests
Dockerfile                     Multi-stage application image
docker-compose.yml             PostgreSQL and application runtime
pom.xml                        Maven build, generation, testing, and reports
```

OpenAPI interfaces and models, MapStruct implementations, static OpenAPI
documentation, reports, and packaged artifacts are generated under `target/`.
They are not committed to the repository.

## Run Locally With Maven

Start PostgreSQL:

```bash
docker compose up -d db
```

Start the application:

```bash
mvn spring-boot:run
```

The API base URL is `http://localhost:8080/api`. Stop the database when it is
no longer needed:

```bash
docker compose down
```

On Windows, `mvnw.cmd` can be used instead of an installed Maven command. On
Linux and macOS, use `./mvnw`.

## Run With Docker Compose

Build and start PostgreSQL and the application together:

```bash
docker compose up --build
```

Run in the background when interactive logs are not needed:

```bash
docker compose up --build -d
```

Inspect application logs with:

```bash
docker compose logs -f app
```

Compose waits for the PostgreSQL healthcheck before starting the application.
Stop the stack with `docker compose down`.

## Environment Variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `DB_USERNAME` | `postgres` | PostgreSQL username used by the application and Compose |
| `DB_PASSWORD` | `postgres` | PostgreSQL password used by the application and Compose |
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://localhost:5432/identity_db` | JDBC URL for direct local runs |

Docker Compose sets `SPRING_DATASOURCE_URL` to
`jdbc:postgresql://db:5432/identity_db` for the application container. Override
credentials through shell environment variables or a local `.env` file. Do
not commit `.env` files or real credentials.

## Testing

Run the complete validation flow with:

```bash
mvn clean verify
```

This command generates sources, compiles the project, runs unit and web-layer
tests, runs Testcontainers integration tests against PostgreSQL, packages the
application, and generates JaCoCo reports.

Docker must be running and accessible to the current user. The tests do not
depend on a locally installed PostgreSQL server or on the Compose database.

## CI/CD

The workflow in `.github/workflows/ci.yml` runs for pull requests and pushes to
`master`.

For every run, CI:

* sets up Java 21 with Maven dependency caching
* runs `mvn clean verify`
* validates the generated JaCoCo and OpenAPI documentation
* validates `docker compose config`
* builds the application Docker image

After a successful push to `master`, CI also generates the Maven site, assembles
the complete Pages artifact, and deploys it through GitHub Pages Actions.

## Troubleshooting

### Docker Is Not Running

Start Docker Desktop or the Docker daemon, then verify access with:

```bash
docker info
```

Both Testcontainers and Docker Compose require a working Docker daemon.

### PostgreSQL Port Conflict

Compose exposes PostgreSQL on the standard host port `5432`. Stop the local
PostgreSQL service or container already using that port, then retry
`docker compose up`. Use `docker ps` to identify running containers.

### Testcontainers Failures

Confirm that `docker info` succeeds for the same user running Maven. Check that
Docker has enough memory, that the daemon can pull `postgres:16`, and that no
local Testcontainers configuration overrides the Docker endpoint incorrectly.
Re-run `mvn clean verify` after Docker is healthy.

### Generated OpenAPI Code

Do not edit generated interfaces or models. Change
`src/main/resources/openapi/identity-api.yaml`, then regenerate with:

```bash
mvn clean generate-sources
```

Generated Java sources are written to `target/generated-sources/openapi`, and
generated HTML documentation is written to `target/openapi-docs`.
